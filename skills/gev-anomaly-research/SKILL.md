# GEV anomaly research

Read the repository’s [agent instructions](../../AGENTS.md) and [workflow chart and step register](../../WORKFLOW.md). Use the [run templates](../../templates/_schema-notes.md) to create a self-contained investigation record.

Discover current GEV capabilities before making observation claims. If GEV is unavailable, state the limit and perform only work supported by accessible evidence. Preserve the distinction between GEV observations, externally reported leads, propagated satellite positions and confirmed events.

Select the relevant adapter:

- [Source access and provenance](../../playbooks/source-access.md): all investigations.
- [Aircraft and GNSS](../../playbooks/aircraft-gnss.md): aircraft tracks, navigation quality and interference hypotheses.
- [Satellites](../../playbooks/satellites.md): orbital catalogs, maneuvers and apparent proximity.
- [Trade impact](../../playbooks/trade-impact.md): claims about freight, rerouting, capacity or commercial consequences.

Carry a broad discovery request through a ranked shortlist, a selected case, quantified evidence, competing falsifiable hypotheses, actual feasible tests, revised verdicts and a final report. Respect explicitly narrower scope. Reuse the method, not the Finland case’s parameters or conclusions.

Use [the Finland chronology](../../examples/finland-gnss/chronology.md) only when the worked example helps explain a decision or failure mode. It is historical evidence, not current traffic. Keep blocked tests distinct from executed negative results, and finish with an honest report even when no causal hypothesis is established.

This skill is distributed inside the repository and uses its relative paths. Keep the repository structure intact when invoking it; it does not install GEV, configure accounts or create recurring work.
