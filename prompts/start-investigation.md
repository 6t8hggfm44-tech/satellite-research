# Reusable investigation prompt

Copy the prompt below into a model that can access this repository. Replace the bracketed question with the new investigation. Optional constraints can specify region, period, entities, available data, budget or a narrower output.

> Read this repository’s AGENTS.md, WORKFLOW.md and relevant playbooks. Investigate: **[new research question]**.
>
> Use available God’s Eye View evidence and dated primary sources. Start by verifying what GEV and the current environment can actually provide. Build a short ranked list of defensible leads, then carry the strongest testable lead through the complete workflow unless I have selected a case or explicitly limited the scope. State reasonable assumptions and continue routine work without unnecessary clarification.
>
> Create a new case with its own dates, variables, thresholds, baselines and competing hypotheses. Preserve source provenance and event-time data. Quantify the anomaly, build a source-linked GEV view when available, specify realistic predictions and falsifiers, and execute feasible tests. Separate what was observed from what is inferred; record missing data and blocked tests honestly. Independently check material calculations and revise any conclusion that the tests weaken.
>
> Deliver a report using templates/report.md, with actual hypothesis-test outcomes, confidence limits, practical significance, source links and a reproducible evidence package. The Finland example demonstrates the method and output form; it does not supply default facts or conclusions. If the evidence is inadequate, the final report should say so. Do not initiate unrequested outreach, purchases or ongoing monitoring.

For a follow-up such as **“test the hypotheses”**, resume the existing run and execute its feasible pending tests. Do not repeat the proposal as though it were an executed result. Preserve prior plans and conclusions, then issue a revised report and correction record.

For **“are you using GEV?”**, audit actual queries and provenance. State exactly what came from GEV, outside reporting, processed archives or assumptions, and repair the workflow within the authorized scope.
